# CI Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a GitHub Actions workflow that runs frontend checks on Linux and Rust checks on macOS against every PR to `main`, and document the GitHub UI steps to require these checks for merge.

**Architecture:** A single workflow file (`.github/workflows/ci.yml`) with two parallel jobs — `frontend` (ubuntu-latest: npm ci, build, test) and `rust` (macos-latest: fmt, clippy, test). Triggered only on `pull_request` against `main`. Merge protection is configured manually per the checklist in the spec.

**Tech Stack:** GitHub Actions, Node 20, Rust stable, `Swatinem/rust-cache@v2`, `dtolnay/rust-toolchain@stable`, `actions/setup-node@v4`.

### Task 1: Add CI workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/ci.yml` with this exact content:

```yaml
name: CI

on:
  pull_request:
    branches: [main]

jobs:
  frontend:
    name: frontend
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build (typecheck + vite build)
        run: npm run build

      - name: Test
        run: npm test

  rust:
    name: rust
    runs-on: macos-latest
    defaults:
      run:
        working-directory: src-tauri
    steps:
      - uses: actions/checkout@v4

      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy

      - uses: Swatinem/rust-cache@v2
        with:
          workspaces: src-tauri

      - name: Check formatting
        run: cargo fmt --all -- --check

      - name: Clippy
        run: cargo clippy --all-targets --locked -- -D warnings

      - name: Test
        run: cargo test --locked
```

- [ ] **Step 2: Validate YAML syntax locally**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"`
Expected: no output, exit 0.

If `pyyaml` is not installed, fall back to: `ruby -ryaml -e "YAML.load_file('.github/workflows/ci.yml')"` — any Ruby on macOS has YAML built in.

- [ ] **Step 3: Verify frontend commands work locally**

Run these from the repo root to confirm the workflow's frontend steps will succeed:

```bash
npm ci
npm run build
npm test
```

Expected: all three commands exit 0. If any fail, stop and surface the failure — the CI would also fail on it and it needs fixing before landing.

- [ ] **Step 4: Verify rust commands work locally**

Run from `src-tauri/`:

```bash
cd src-tauri
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cd ..
```

Expected: all four commands exit 0. If `cargo fmt --check` fails, run `cargo fmt --all` and commit the formatting fix as a separate preparatory commit before committing the workflow. If clippy fails, fix warnings or (if out of scope for this task) report them to the user and stop — do not merge a workflow that will immediately fail on `main`.

- [ ] **Step 5: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add PR workflow for frontend and rust checks"
```

If preparatory fixes were needed in Step 4 (e.g. a `cargo fmt` pass), commit those in their own commit first with a message like `style: cargo fmt` before the workflow commit.

- [ ] **Step 6: Report GitHub UI follow-up to user**

After the plan is complete, tell the user:

Next, open a PR from this branch to `main` so the `frontend` and `rust` checks register, then in GitHub UI go to **Settings → Branches → Add branch ruleset** for `main` and enable: Require PR before merging; Require status checks (`frontend`, `rust`) with "Require branches to be up to date"; Block force pushes; Restrict deletions.
